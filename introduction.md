In early 2024, I recognised that there might be a novel approach based upon a
single, fundamental insight:

**While one cannot tile hexagons with hexagons, one can tile half-hexagons
with half-hexagons.**

While this journey is far from over, this one insight has already yielded
really exciting results — not all of which are novel, and many of which might
be advantageously used in any hierarchic grid based on triangular projections.

---

## The Hex9 Environment

Hex9 depends on a global, hierarchical triangular grid generated by subdividing
the faces of a fundamental **octahedron**, whose vertices are fixed at the poles
and at 0°, 90°, 180°, and 270° along the equator.  This provides a consistent
tessellation suitable for multi-resolution spatial analysis.

A key advantage of using an octahedron is that each vertex connects an **even**
number of triangular faces (four at the poles, four along the equator
intersections).  This allows each triangular face to be subdivided into three
sub-triangles forming a half-hexagon, which aligns perfectly across neighbouring
faces.  By contrast, an icosahedron has vertices with five faces, making this
half-hexagon alignment impossible without distortion or irregular shapes.

The following image demonstrates the importance of using polyhedra whose
vertices have an even number of edges:

![](images/octahedron.png)*Octahedra have four faces at each vertex*

This image also shows the 12 'Layer 0' hexagons, each of which straddles two
faces (*octants*) — a defining feature of Hex9.

Layer 1 is a subdivision of Layer 0: each Layer 0 hexagon divides into 9
sub-hexagons (six whole hexagons and six half-hexagons).  Strictly speaking,
we are subdividing the *regions* of the octahedron faces, of which the hexagons
are an emergent feature.

![](images/octahedral_net_a.png)*Layer 1 as an octahedral net*

## Architecture Overview

Hex9 is two things layered on top of each other:

### 1. The CRS Pipeline

A chain of coordinate domains transforms any point on the WGS84 ellipsoid into
authalic barycentric coordinates on the octahedron:

```
g_gcd → r_gcd → c_ell → c_oct → b_raw → b_oct
```

* `g_gcd` — standard lon/lat (degrees)
* `r_gcd` — lon/lat in radians (internal form)
* `c_ell` — 3D Cartesian ECEF on WGS84
* `c_oct` — Cartesian projected onto the unit octahedron (AK formula)
* `b_raw` — geometric (unwarped) per-face barycentric coordinates
* `b_oct` — authalic-warped barycentric coordinates; the grid's home domain

The `c_ell → c_oct` forward transform uses a closed-form tangent normalisation
(the AK formula).  The reverse has no reliable closed form and is solved
numerically by a domain-specific hierarchical root-finder that exploits the
fractal structure of the grid.

For display, `b_oct` is projected onto a flat 2D net (`n_oct`).  This
display projection is fully independent of any cartographic map projection
chosen for the final output — the grid geometry is unaffected by the choice
of map view.

A PROJ-compatible plugin (`h9_boct`) exposes the full `g_gcd ↔ b_oct` pipeline
to any PROJ-aware application.

### 2. The DGGS

The grid itself lives in `b_oct` space.  The octahedral face is subdivided
hierarchically using the half-hexagon tiling.  Each subdivision increases the
resolution by a factor of 9.  Hexagonal addresses are deterministically
derivable from `b_oct` coordinates — no precomputed databases required.

See [precision.md](precision.md) for the full domain and projection tables,
root-finder detail, and accuracy benchmarks.

See [enumeration.md](enumeration.md) for the mathematical foundations of the
half-hexagon tiling and the address system.

## The half-hexagon insight

The plane can be tiled using the 1:9 half-hexagon hierarchy:

![49_tilings](images/49_tilings.png)

Of the 49 possible 1:3 tilings of the half-hexagon, eight mirror pairs can
tile the plane with hexagons.  Of those, exactly one has a symmetry other than
wallpaper group `p1` — it has symmetry `p31m`, which works both on the plane
and can be lifted to the octahedron.

The use of half-hexagons ('regular' trapezoids composed of three equilateral
triangles) as the primary fundamental resolves many of the issues that arise
in hexagonal hierarchies.

Earlier work (c. 2010) explored something similar to the H3 approach, but
lacked a grid-layer transition that preserved shape and an intuitive address
system.  The current Hex9 approach resolves both.

![h9a9.png](assets/docs/h9a9.png)

Below is the basic unit hexagon divided into the 18 half-hexagons that compose
it.  The numbering is one way of indexing the half-hexagons for planar tiling.
When tiling the octahedron, a small additional rule handles edge transitivity.

![index_units.png](assets/docs/index_units.png)

The plane tiled using this generator:

![tiling.png](assets/docs/tiling.png)

A hexagonal grid hierarchy — outer hexagon in white, with successive lower
hierarchies in green, blue, and red.  The hierarchy is unlimited in depth.

![hierarchy](assets/docs/hierarchy.jpg)

While independent of the display projection, the method *cannot* be used on
an arbitrary polyhedron projection.  The fundamental shape relies on
chained mirror-pairs and only works on polyhedra with an **even** number of
edges at each vertex.  It does not lend itself to icosahedral maps (five edges
per vertex).

This is not a major issue — the octahedron is highly suitable for this
hierarchy.  Although the octahedron tends towards greater area distortion than
the icosahedron when used as a cartographic projection, for generating
hexagonal grid addresses in `b_oct` space it works perfectly adequately.

## Grid addressing

Addresses use subtended regions rather than axis-oriented coordinates.
Benefits:
* A single string (unlike lat/lon or OS grids).
* The string length encodes the hierarchy level.
* Locality is directly expressed — no remote origin to remember.
* Shortening the address (with care) yields the layer ancestry.

Coordinates are in base 9, with a metadata tail for exact reversal.
The full address system is described in [enumeration.md](enumeration.md).
